Deploy Yotara on your own server. No vendor lock-in, no data leaving your infrastructure.

Before you start

Self-hosting is a small, one-time setup — but it does ask a few things of you. Make sure you're comfortable with these before you begin.

key

Set a strong secret

You must generate a BETTER_AUTH_SECRET to sign sessions. Without it the stack refuses to boot.

save

Plan for persistence

Your data lives in a SQLite file. Keep it on a named volume or mounted path so it survives container restarts.

backup

Back it up

You own the data, which means you own the backups. Schedule a copy of the database file off-server.

dns

Expose it safely

For real use, put it behind a domain with TLS. The included nginx config serves plain HTTP on port 80. Add a TLS-terminating reverse proxy (e.g. Caddy, nginx with certbot, or Cloudflare Tunnel) in front of it.

Method 1

Quick start with Docker 

$ docker run -d \
  --name yotara \
  -p 8080:80 \
  -e BETTER_AUTH_SECRET=$(openssl rand -base64 32) \
  apauldev/yotara:latest

→ Open http://localhost:8080

Method 2

Recommended — Docker Compose

Create a docker-compose.yml in your project directory: 

services:
  api:
    image: apauldev/yotara-api:latest
    environment:
      DATABASE_URL: /data/yotara.db
      BETTER_AUTH_SECRET: ${BETTER_AUTH_SECRET?set a strong secret}
    volumes:
      - yotara_data:/data

  frontend:
    image: apauldev/yotara-frontend:latest
    ports:
      - "8080:80"
    depends_on:
      - api

volumes:
  yotara_data:

Then run:

$ docker compose up -d

→ Open http://localhost:8080

System requirements

check_circle Docker installed (20.10+)
check_circle 512MB RAM
check_circle 1GB disk space
check_circle Linux x86_64 or arm64
check_circle OpenSSL to generate a BETTER_AUTH_SECRET

That's it. No external database, no Redis, no email server required. Generate your BETTER_AUTH_SECRET with openssl rand -base64 32 and export it before docker compose up.

Production checklist

Happy with the quick start? Before you rely on it day to day, run through this list.

  • check_circle Use a strong, unique BETTER_AUTH_SECRET and keep it out of version control and shell history.
  • check_circle Serve over HTTPS with a real domain and a valid certificate — the stack ships security headers, but TLS is on you.
  • check_circle Persist the database on a named volume (the Compose file does this) or a backed-up mount.
  • check_circle Automate backups of the SQLite file and test a restore occasionally.
  • check_circle Pin your image tag for reproducible upgrades, then review the changelog before bumping.
  • check_circle Restrict network access with a firewall; only expose what you intend.
